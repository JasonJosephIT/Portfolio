# /place-image — retired

**Do not run this command. The pipeline it drove no longer exists.**

This command used to hand each pending submission to a subagent that edited
`.gallery` and `.project-grid` into `art.html` and `tech.html` by hand, using
the drag overlay's pixel layout (`after_selector`, `width_pct`,
`free_position`, `x_pct`, `y_px`).

Every part of that is gone:

- `art.html` and `tech.html` are **generated**. They carry "Generated by
  scripts/build-portfolio.mjs … Do not edit by hand." and are listed in
  `content/generated-pages.json`. Any edit made to them is overwritten by the
  next `node scripts/build-portfolio.mjs`, and reported as drift by
  `node scripts/build-portfolio.mjs --check` until then.
- The layout keys above are **refused** on the way in: `isLegacyLayout` in
  `admin/content-model.mjs` recognises them precisely so a pixel offset
  measured against a page that no longer exists cannot be reinterpreted as
  structured content.
- The CSS classes it wrote — `.gallery`, `.project-grid`, `.project-card`,
  `.tech-tags`, `.project-link` — have been removed from `styles.css`.

## What replaced it

1. **Review and draft** in the content editor at `/admin/content/`: pick the
   submission under **Inbox**, press **Write draft**, fill in the title and alt
   text, **Save proposal to submission**, then **Export proposal file**.
2. **Import** the exported file:
   `node scripts/import-portfolio.mjs --input <file> [--download]`. It writes
   draft records into `content/portfolio.json` and nothing else.
3. **Publish** in the editor, export `content/portfolio.json`, and save that
   download over the file yourself — the browser cannot write the repository.
4. **Build**: `node scripts/build-portfolio.mjs`, then
   `node scripts/build-portfolio.mjs --check`.
5. **Deploy**, then `node scripts/mark-placed.mjs <id>` for each submission that
   is now live, so the inbox stops re-offering it.

`docs/portfolio-content.md` is the full description of that workflow, and
`docs/launch-checklist.md` walks it step by step.

This file is kept, rather than deleted, because the command is Jason's tooling
and removing it is his call.
