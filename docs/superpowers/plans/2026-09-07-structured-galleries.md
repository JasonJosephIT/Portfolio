# Structured Galleries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Fulfill Jason's portfolio design brief with accessible static Art/Tech galleries, canonical detail pages, and a structured owner workflow.
**Architecture:** One canonical authoring document in content/portfolio.json. Supabase remains the existing authenticated ingestion inbox; versioned layout proposals are import handoffs. Node generates published-only HTML; progressive JS enhances filters, expansion, color and return context. A public build excludes canonical source/drafts.
**Tech Stack:** Existing plain HTML/CSS/browser JavaScript; dependency-free Node ES modules and node:test. No migration or deployment.

## Global Constraints

- Preserve existing Home navigation, Jason’s name, chosen hero, and quotation unless a later task explicitly changes them.
- Do not restore previously removed personal photos or invent public projects, skills, testimonials, or outcomes.
- Use the existing stack where practical; structured layouts do not require a framework migration.
- No absolute-positioned canvas or arbitrary visitor-facing layout controls.
- Public browsing must not depend on admin authentication or editor scripts.
- Draft records never appear in public lists or count totals.
- Favorites keep their curated order. Removing a favorite leaves its source record intact.
- A piece opens the same canonical detail view wherever it appears. A project opens its collection, not an arbitrary first piece.
- These are the user-selected assets, not verified examples of a particular Caribbean textile tradition.
- Do not run remote migrations, import existing remote photos, mark remote submissions placed, or deploy.
- Production output must exclude canonical authoring JSON and drafts. Existing inbox storage remains unchanged.
